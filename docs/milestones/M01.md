## M01-T03 mandatory accessibility remediation (2026-11-21)

Status: **AWAITING INDEPENDENT CODE GUARDIAN REVIEW**. This is implementation and developer verification, not independent Code Guardian approval. D011 is **APPROVED — LOCAL DEVELOPMENT** by the repository owner (recorded 2026-11-21). M01 remains in progress; **PPG-001 remains OPEN and BLOCKING for production**. No M01-T04 work is authorized or included.

Findings addressed:

- **T03-001 (Medium):** keyboard focus was lost at the 1024px desktop breakpoint. In Edge, opening the mobile menu at 800px and resizing to 1280px reproduced focus falling to BODY, `aria-expanded="true"`, and stale mobile-open/backdrop state before the fix.
- **CG-T03-R01 (Medium):** responsive-transition regression coverage was missing. Added 15 automated cases, including browser blur-before-media-event ordering and listener cleanup.
- **CG-T03-R02 (Low):** defect/remediation documentation was missing. This record and the architecture's responsive-navigation description document the implementation, verification, and limitations.

Implementation:

- `AppLayout.tsx` observes exactly `(min-width: 1024px)` with `matchMedia` and removes its change listener on unmount. Entering desktop resets mobile navigation to closed, so `aria-expanded` is false and the backdrop/close button are removed.
- `Sidebar.tsx` exposes a ref to its existing Dashboard link as the visible desktop focus destination. Only focus on a disappearing mobile toggle/close button is transferred; a focused Dashboard link or other visible content is preserved.
- Returning to mobile leaves navigation closed. If Dashboard was focused, focus transfers to the visible menu toggle because the link is now in the hidden sidebar.
- Focus/blur capture is scoped to the shell and remembers a disappearing control when CSS clears active focus before the media event. Ordinary blur is cleared, preventing later resize from reclaiming deliberately released focus. No document-wide focus listener was introduced.
- Normal mobile close/toggle/Escape behavior still restores toggle focus. The close callback checks the live media state and never focuses the hidden desktop toggle. Desktop Dashboard navigation and Escape do not invoke hidden-control focus restoration.
- No CSS breakpoint changes or dependencies were needed. Existing `(min-width: 1024px)` styling is preserved. Backend code and migrations were not modified.

Automated regression verification:

- Added deterministic `matchMedia` test support with mutable matches and dispatched change events, rejecting unexpected query strings. Each test gets isolated media state; global stubs are restored after cleanup.
- New cases cover open-menu reset, backdrop removal, close-button/toggle focus transfer, preservation of Dashboard and unrelated visible-control focus, initial desktop mount without focus movement, return-to-mobile closure/focus, desktop Escape, mobile Escape before/after transitions, desktop Dashboard activation, CSS blur ordering for both mobile controls and Dashboard, deliberate blur without focus recovery, and listener removal on unmount.
- Before implementation, seven of the first ten new cases failed against the original code. Three additional blur-order cases failed against the initial media-event-only implementation. These failures established the missing state and focus behavior before the final implementation.
- `npm run lint`: passed. `npm run test:run`: **3 files, 52 passed, 0 failed** (37 existing plus 15 new). `npm run build`: TypeScript and Vite passed. Both `npm audit` and `npm audit --omit=dev`: **0 vulnerabilities reported**. A clean advisory audit does not establish complete security.
